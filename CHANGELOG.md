# Changelog

## 2026-10-11

- Fix passwords sometimes showing up different from what was generated. The results are returned as HTML, and the character pool includes `&`, `#`, and `;`, so a password containing a sequence like `&#9`, `&#65`, `&lt`, or `&not` was decoded by the browser as a character reference: it showed a tab, `A`, `<`, or `¬` instead, sometimes a character outside the pool. In a simulation of 20,000 default requests (30 passwords of 16 characters), about 0.9% had at least one altered password. Each password is now HTML-escaped with `markupsafe.escape` before the list is joined, so the browser shows exactly what was generated. The results are still the same bare `<BR>`-joined list. File changed: `services/web/project/__init__.py:5,66-68`.
- Read the `exclude_special` checkbox with `request.form.get` instead of a `try`/`except Exception` around `request.form[...]`. Same behaviour, and it no longer hides unrelated errors. File changed: `services/web/project/__init__.py:26`.
- Write `FROM ... AS builder` and `ENV KEY=value` in the Dockerfile. The lowercase `as` and the space-separated `ENV` form made BuildKit print `FromAsCasing` and `LegacyKeyValueFormat` warnings on every build. File changed: `services/web/Dockerfile:6,12-13`.
- Add tests in `services/web/tests/test_app.py` (pytest with Flask's test client). The project had none. They cover the home page, password counts and lengths, both character pools, the fallbacks to defaults for blank, non-numeric, zero, negative, and decimal input, the caps, and the HTML escaping above. Two of them fail on the code before the escaping fix. `CLAUDE.md` now has the commands to run them and flake8.
- Change the [AI Code Rating](https://aicoderating.com/spec/0.1/) from B2b to B3b (AI Share: 51–75%). The new tests take AI's share of the code from about 36% (66 of 179 non-blank lines) to about 52% (roughly 120 of 230), not counting the vendored daisyUI plugin. The "How AI Was Used" section now mentions the escaping fix and the tests. Files changed: `ACR.md:2,9,15`, `README.md:4`.
- Remove `gcc` from the Docker builder stage and `netcat-openbsd` from the final stage. `gcc` was only needed to compile psycopg2, which was removed with the database packages, and nothing used `netcat`. The final image is about 39 MB smaller (245 MB to 206 MB), and the build no longer installs a compiler. File changed: `services/web/Dockerfile:17,67`.
- Note in `CLAUDE.md` that the password list returned by `POST /` is unstyled on purpose.
- Add an `ACR.md` file with the project's [AI Code Rating](https://aicoderating.com/spec/0.1/), B2b (Maintainer: Experienced · AI Share: 26–50% · Oversight: Reviewed), so readers can see how much of the code AI wrote and how carefully it was checked, and add its badge to `README.md`. AI wrote 66 of the 179 non-blank code lines (about 36%), not counting the vendored daisyUI plugin.
- Fix the README's installation step to load `http://IP_ADDRESS:8085` instead of `https://`. The container serves plain HTTP (gunicorn on port 5000, published on 8085, with no TLS), so the `https://` link failed with a TLS error.
- Add automatic dark mode that follows the visitor's system colour scheme, with no toggle or JavaScript. The page only had daisyUI's light `bumblebee` theme, set with `data-theme="bumblebee"` on `<html>`, so it stayed light for visitors who prefer dark. daisyUI's `business` theme is now built in as `--prefersdark`, which puts its colours inside `@media (prefers-color-scheme: dark)`; the page background, text, form, and button all switch with it. The `data-theme` attribute is removed, because daisyUI only applies the dark theme to a root without one. A `color-scheme` meta tag tells the browser about both modes before the CSS loads, which avoids a white flash. In dark mode the Generate button uses a navy blue instead of `business`'s orange accent (`business`'s primary darkened from `oklch(41.703% .099 251.473)` to `oklch(34% .085 251.473)`, which raises the button text's contrast from 6.0:1 to 8.3:1), and the form and its fields keep `bumblebee`'s rounder corners instead of `business`'s near-square ones. These match the dig project. Light mode looks the same as before. The password list returned by the form is plain text, so it still shows in the browser's default colours.
  - `services/web/project/styles/app.css:7,10-19`: add `business --prefersdark` to the daisyUI themes, and set a darker `--color-primary` and `bumblebee`'s `--radius-*` values for dark mode.
  - `services/web/project/templates/home.html:2,4,23`: remove `data-theme="bumblebee"`, add the `color-scheme` meta tag, and add `dark:btn-primary` to the Generate button.
  - `CLAUDE.md`: add a dark mode note.
- Build Tailwind 4.3.3 and daisyUI 5.7.46 CSS at Docker build time instead of loading them from jsDelivr. The page used the in-browser Tailwind compiler, a floating `daisyui@5` tag, and a separate themes file pinned to `5.0.0`, so every visitor downloaded and ran a third-party compiler, and upstream releases could change the styling without any change here. The build now produces a single minified `app.css` (about 27 KB) with only the classes the template uses and the `bumblebee` theme.
  - `services/web/Dockerfile:17-31,39-40,75`: the builder stage downloads the Tailwind standalone CLI (checksum-verified, amd64 and arm64) and builds the CSS; the final stage copies in `app.css`.

  - `services/web/project/templates/home.html:8`: load `app.css` locally instead of the three CDN files.
  - `.gitignore`: ignore the generated `project/assets/app.css`.

- Add `<!doctype html>`, `lang="en"`, and a viewport meta tag to the page, and remove two classes and a click handler that did nothing. Without a doctype the browser rendered the page in quirks mode, which Tailwind's base styles don't expect; without `lang` screen readers had to guess the language; and without a viewport tag phones showed a zoomed-out desktop layout. `form` isn't a daisyUI class and `justify-left` isn't a Tailwind class (it's `justify-start`), so neither did anything. The Generate button's `onclick="$('#loading').show();"` called jQuery, which the page doesn't load, to show a `#loading` element that doesn't exist, so every click logged a `$ is not defined` error. File changed: `services/web/project/templates/home.html:1-4,15-16,24`.
- Update Python from 3.9 to 3.14, Flask from 2.3.0 to 3.1.3, Werkzeug from 2.3.0 to 3.1.9, gunicorn from 20.1.0 to 26.2.0, and flake8 from 3.9.1 to 7.4.1, and remove Flask-SQLAlchemy and psycopg2-binary. Python 3.9 reached end of life in October 2025, so it no longer gets security fixes. gunicorn 20.1.0 has a request-smuggling vulnerability (CVE-2024-1135, fixed in 22.0.0). The app never used a database, so the two database packages were only making the image bigger. gunicorn 26 also adds a control socket for its `gunicornc` tool, which this app doesn't use; the `app` user can't create it in `/home/app/.gunicorn`, so it's turned off with `--no-control-socket`. flake8 7 reports W503 (line break before a binary operator), which conflicts with W504 and current PEP 8 advice, so it's ignored alongside the existing E501 and F401.
  - `services/web/requirements.txt`: new versions, and drop Flask-SQLAlchemy and psycopg2-binary.
  - `services/web/Dockerfile:6,21,23,35`: `python:3.14.7-slim` for both stages, and flake8 7.4.1 with W503 ignored.
  - `docker-compose.yml:10`: add `--no-control-socket` to the gunicorn command.
  - `CLAUDE.md`: update the lint and test commands, note the control socket setting, and drop the note about the unused packages.
- Generate passwords with Python's `secrets` module instead of `random`. `random` is not cryptographically secure, so its output could in principle be predicted. The output format, defaults, and character pools are unchanged. The two `random.shuffle` calls were dropped, since they add nothing once each character is picked independently and securely.
- Cap each request at 1,000 passwords of up to 256 characters. There was no limit before, so one request for millions of passwords could keep a gunicorn worker busy until it timed out (200,000 passwords already took over 4 seconds). Larger values are lowered to the cap.
- Fall back to the defaults (30 passwords, 16 characters) when a field is non-numeric, zero, or negative. Before, non-numeric input raised a `ValueError` and returned a 500 error.
